## Objetivo y límites

Avance de validación 02-10-2026: `src/shared/bridge-server-message.ts` centraliza la validación de mensajes de negociación recibidos por popup y content script. Rechaza campos extra y versiones malformadas; conserva `ready` sin versión para reconocer apps anteriores. Ambos clientes ignoran `compatible` antes de enviar `hello`. Las pruebas de popup y reconexión cubren esa secuencia y campos inesperados; `npm run verify` pasó con 100 pruebas. La revisión del resto de límites y las pruebas reales siguen abiertas.

Migrar la lógica de Lyrics a TypeScript y separar responsabilidades sin cambiar el comportamiento visible ni el protocolo local por accidente. La app Electron, la extensión Manifest V3, las pruebas y el instalador deben seguir funcionando durante la migración. Los asuntos de derechos, tienda, firma y publicación permanecen en `TODO.md` como trabajo independiente.

**Diagnóstico medido:** no hay actualmente archivos fuente de más de 500 líneas. Los mayores son `desktop/main.js` (aprox. 299 líneas), `desktop/renderer.js` (225), `desktop/lyrics-provider.js` (170) y `extension/content.js` (121). La razón para separar código es la mezcla de responsabilidades y dependencias, no alcanzar un número arbitrario de líneas. Línea base: 70 pruebas locales correctas con `node --test` el 29-09-2026.

**Criterio de diseño:** cada módulo debe tener un propósito claro y una API pequeña. Evitar tanto archivos que mezclen subsistemas como un archivo nuevo por cada función trivial. La validación en ejecución de datos externos sigue siendo necesaria aunque TypeScript compruebe los tipos.
